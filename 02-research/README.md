# 02 Research

Read the understanding record and derive a small, diverse search set: the customer's problem,
solution category, task/use case, alternatives, and buying objections. Use the configured
language and market. Expand from results when they reveal different customer terminology.
The user does not supply seeds unless they want to steer them.

Inspect integration availability. Use GSC when present, but an empty property does not block
research. Use `research_market.py` with an agent-derived query/target and the provider route
in [Terminal research APIs](research-apis.md). Its durable receipts and daily call reservations
support unattended research within existing authority. Firecrawl search/scrape, Brave search,
DataForSEO keyword ideas/SERPs/domain research, SociaVault, existing clients, or the host's web tools
can supply complementary evidence. These are alternatives; do not require every provider.
Record source URL, provider/query, geography/language, observed date, relevant exact excerpt,
and a local snapshot of the actual response. Redact credentials and unrelated private data.

Read pages behind search results rather than treating snippets as a market study. Separate
commercial competitors from sites competing for the same query. Investigate intent, covered
questions, missing useful detail, freshness, credible proof and business fit. Customer/support
questions and existing search demand can support a low-volume opportunity; absence of volume
is unknown, not zero or proof of no demand. Never manufacture competitor weaknesses.

Produce at least two concrete opportunities, including improving an existing page when
feasible. Consider a useful calculator, template, integration guide, product comparison,
category page, service page, dataset, tutorial or product-led sharing surface. Explain the
distinct contribution this particular owner can make. Don't assume every answer is a blog post.

Record `research` with external evidence, questions, competitor observations, opportunities,
claims and unknowns. Local source code supports product claims; it cannot establish market
demand by itself. A blocked provider should leave a failure artifact and trigger another
available route. If all external evidence is unavailable, draft hypotheses and do diagnosed
technical repairs; don't mark demand research complete or invent keywords to pass a gate.
