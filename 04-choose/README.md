# 04 Choose

Inspect active interventions and learning first. Resume uncertain deployments, avoid duplicate
URL ownership, and don't repeat a failed tactic without stating what new evidence changes it.
Compare feasible actions from current research: audience/intent, original value, conversion
path, competition, effort, implementation risk and demand evidence. Include leaving a sound
page alone when alternatives add little. Business-value scores are judgments, not forecasts.

Use `assess_opportunities.py` to validate candidates. Its ordinal sorting is a starting point;
the agent chooses with a rationale grounded in the actual evidence. A technical regression
can use a diagnostic-backed repair without waiting for market research. Product/category
pages, tools, integrations and editorial content are peers rather than mandatory stages.

Write the actual `run_growth.py` brief before source edits: current positioning digest,
selected candidate and alternatives, hypothesis, reader need, original value, target paths,
all source dependencies, test/build/deploy argv, assertions, baseline and rollback plan.
Do not ask the owner to assemble this JSON. Capture baseline evidence of what is deployed;
a supplied snapshot must be identified as such. At least one assertion should distinguish
the desired intervention from current production, including metadata-only repairs.

Select one bounded intervention per cycle. Scope it so implementation, rendered inspection
and relevant checks can finish. A creative tactic still needs an acquisition mechanism:
who searches for or encounters it, why it deserves discovery/citation, how readers find the
offering, and what observable result would support or weaken the hypothesis.
