# Recurring first-party growth cycle

Run in the configured website repo. Read its project instructions and the installed
seo-growth skill using its actual path. Reuse the user's existing authorization and budget.

1. Run run_growth.py --stage status. Resume one unfinished intervention before starting new work.
   For deployment_uncertain, inspect hosting status and verify; never blindly redeploy.
   For missing credentials, evidence or factual input, record the exact blocker and leave
   the item actionable. Do not create filler to meet a publishing cadence.
2. Review due verified interventions first. Fetch mature traffic windows using traffic_report.py,
   or the configured analytics export, and evaluate the same URLs/property/cohorts. Read the
   actual channel results and caveats. Record retain/refine/revert/defer with a reason and costs.
   Small samples need more observation; API mention probes never substitute for traffic.
3. If capacity remains, run seo-maintain and diagnose serious regressions. For discretionary
   growth, run run_strategy.py --action status and follow the earliest missing/stale section
   of workflow/README.md: understand → research → position → choose → execute → learn.
   Generate the business profile, search seeds, external API research, positioning and copy
   briefs yourself. Use research_market.py under the configured allowance and existing scope;
   preserve actual source responses. Do not ask the owner to supply keywords or strategy JSON.
   Read the packet's prior observations and decisions before choosing the next hypothesis.
   Compare at least two feasible actions using current demand evidence and owner value.
   Select at most one intervention per cycle, avoiding duplicate URL ownership by active jobs.
4. Create its durable brief before editing. Work in the original website framework, validate
   source and rendered output, then use authorized deployment and production verification.
   Without deployment authorization, leave a concrete validated change ready for review.
5. Report a shipped/verified change, outcome decision, failed check or input needed. Stay quiet
   when nothing changed or needs action. Never report local builds or generated content as traffic.

Use the host's normal scheduler. For Codex, attach this prompt to the target project/task's
recurring automation using its scheduler UI/tool. Other agents can invoke run_cycle.py through
cron or CI with SEO_REPO_ROOT pinned and an explicit agent argv command in config. Installing
skills or generating a handoff file does not activate a scheduler. Inspect the first scheduled
run and its next-run time; record scheduler ID/timezone/owner in the target repo's operations note.
