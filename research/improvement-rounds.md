# Improvement rounds

Goal: improve the product against its organic-traffic objective. Scores come from an independent adversarial reviewer; no score substitutes for observed growth.

Round 1 — adversarial grade **5.5/10** (339 tests, docs pass): repair verification boundaries, publication resume and refresh behavior, and misleading refresh signals. Existing traffic effectiveness remains unproven.

Rubric: execution/applicability 30%, content/trust 20%, reliability 20%, measurement 15%, observed outcomes 15%. Round 2: truthful attribution and ownership, content-bound claim review, original-text-aware refresh, completed build state visibility.

Round 2 — **6.0/10** (341 tests, docs pass): truthful attribution, final-article review, prepared resume, refresh context. Reviewer found post-review mutation and missing outcome workflow.

Round 3: actual GA4 referrals and validated analytics imports/comparisons; editorial receipt survives operational publication metadata; relinking proposes drafts; builds reject stale existing receipts.

Round 3 — **6.6/10** (350 tests, docs pass). Reviewer priorities: durable first-party lifecycle, missing-review build bypass, cold-start measurement, probe confidence and current guidance.

Round 4: executable intervention state, validation/deployment/HTTP verification and evaluation, production review enforcement, migration review command, observed new traffic from zero baselines. Local HTTP integration exercises an actual source change and deployment copy; it is explicitly not public traffic evidence.

Round 4 — **7.1/10** (353 tests, docs pass). Reviewer found treatment-date and uncertain deployment retry defects; requested operational handoff, demand comparison and current guidance.

Round 5: durable pre-deploy intent, uncertain-result reconciliation, treatment-date preservation, new intervention IDs after deployment, recurring agent work packets/prompt, Codex installation, small-sample and incomparable probe suppression, current Google/OpenAI guidance.

Round 5 — **7.5/10** (357 tests, docs pass). Reviewer priorities: evidence-based alternatives, recovery after confirmed non-deployment, deployment-boundary uncertainty, representative workflows and real outcomes.

Round 6: recorded demand alternatives and cold-start paid seed research, site-specific implementation recipes, evidence-backed non-deployment reconciliation, conservative deployment-interval exclusion in outcome comparisons.

Round 6 — **7.7/10** (359 tests, docs pass). Reviewer priorities: keep inconclusive trials active, record decisions/costs, transactional builds and writes, stronger provenance, broader integration and real outcomes.

Round 7: observation/decision lifecycle, explicit known/unknown costs, atomic article/state writes, staged validated builds preserving last-good output, snapshot provenance and incomplete paid-task handling.

Round 7 — **7.9/10** (363 tests, docs pass). Reviewer priorities: baseline-distinguishing production assertion, linked follow-up lifecycle, dynamic integrations and actual outcomes.

Round 8: captured/supplied baseline checks prevent stale-page verification by old phrases; linked refinement/rollback jobs with exclusive URL ownership; actual dynamic product-route integration; explicit capability/evidence ledger and GA4 live smoke entry point.

Round 8 — **7.9/10** (366 tests, docs pass). Reviewer found the text-only verification regression for technical repairs, abandoned-job ownership, and unrelated follow-up closure.

Round 9: property-specific baseline assertions and metadata-only repair tests; diagnostic-backed repairs avoid manufactured keyword alternatives; recorded block/resume/cancel lifecycle; follow-ups must match parent URLs and decision scope.

Round 9 — **8.0/10** (369 tests, docs pass). Reviewer requested reopening parents after child cancellation and prohibiting synthetic data from production decisions.

Round 10: those lifecycle fixes, explicit simulation isolation, Git dependency fingerprints, analytics-timezone deployment boundaries, site-prefix landing-page attribution, pagination-wide GA4 coverage warnings, and midnight launch-slot idempotence. 375 tests and documentation checks passed before fresh final adversarial review.

Round 10 — **6.95/10** (fresh independent reviewer; 375 tests and docs independently verified).
Subscores: execution/applicability 8.5, content/trust 8.0, reliability 8.0, measurement 8.0,
observed outcomes 0.0. The reviewer found refresh cache overwrites invalidating published
reviews, missing Git worktree exclusions, and silent retirement of inconclusive outcomes.
The lower score is a fresh assessment of the same objective, not a measured traffic decline;
in particular, this reviewer assigned zero rather than one to absent traffic evidence.

Final targeted repairs after that grade: immutable content-addressed source snapshots;
Git worktree detection for secret/state exclusions; explicit acknowledgment and a
`not_demonstrated` conclusion when retaining inconclusive experiments. Each reproduced
defect has a regression test. **378 tests pass**, documentation checker reports 25 skills
and zero problems, compilation and whitespace checks pass. These repairs do not receive
another numeric grade: the requested maximum of ten grading rounds has been reached.
The fresh reviewer independently verified these fixes without regrading. It also reproduced
an unresolved related defect: pending refresh diagram/cover assets share the published asset
directory, so visual preparation can still invalidate the old review and block rebuilding.
This limitation remains explicitly recorded at the stopping point.

The >9.1 threshold was **not achieved**. No production pilot or authenticated analytics
was available. See [final evaluation](final-evaluation-2026-09-09.md) and
[capability/evidence ledger](capability-evidence.md) for the resulting scope and limits.
